### ⚠️ 没把握的地方（请重点看这几处）

**1. OJ 题号没有联网核验 —— 这是最大的风险，也最难自动检出**

讲义与样卷引用了约 60 道题。LeetCode 的题号/题名我把握较大；
**OpenJudge `cs101.openjudge.cn` 的编号风险明显更高**（如 03704、22068、24591、
18160、19930、28046、04123、02754、22158、24729、02524、01611、07734、04078、
22161、01258、05442、09202、05443、02502、02299、02734、02694、02406、27653）。
这些是从模型知识里写出来的，**没有逐条打开链接确认**。闸门验不了这一类。
→ **请优先核这一项**；错一个编号，学生就找不到题。

**2. 讲义里绝大多数代码只验了语法，没验语义**

上表之外的实现（各类排序、图算法、DP、堆、并查集、树遍历……）都是标准算法，
但**没有在本轮实际执行**。它们是给学生照抄的，边界条件（空输入、n=1、重边自环）
和复杂度声明值得抽查。

**3. 样卷的"数据构造建议"只是建议，没有真造数据**

第 17 周每题写了卡时/卡错数据的构造思路（如"n=2×10⁵ 随机 1000 个姓名卡掉
`list.count()`"），但**我没有真的生成这些数据、也没有用错误算法去验证它们真能卡住**。
命题时必须自己造一遍并实测。

**4. T4 的深递归在真实 OJ 上可能 RE**

链状树 n=10⁵ 在本机 CPython 3.12 下跑通了（新版把 Python 帧移出了 C 栈），
但**旧版 CPython / 评测机的 C 栈更小，可能段错误**。我在题解里加了
`threading.stack_size(1<<26)` 的兜底写法与提醒，但**没有在真实评测环境验证**。

**5. 讲义 ⇄ 课件的一致性是人工保证的**

闸门能验"配对存在"，验不了"讲的是同一件事"。我是照着讲义写的课件内容模块，
但两边是分别写的，可能有口径漂移（例如某个复杂度在讲义写 O(E log V)、
课件写 O(E log E)）。**这是人工审查的重点。**

**6. 周次 → 月份的映射是猜的**

文件名 `YYYYMM` 按"第 2 周 ≈ 9 月上旬"推算。若重庆实际教学日历不同，需批量重命名。
已记在 PLAN 的 Q-1。

**7. LibreOffice 渲染 ≠ PowerPoint 渲染**

排版检查是用 LibreOffice 做的。字体回退、行距、表格自动增高在真 PowerPoint 下
可能略有差异。**表格行高我是按 LibreOffice 实测行距（约 34pt）校准的**——
如果在 Office 里发现表格说明文字压住最后一行，就是这个常数需要重调
（`courseware/deck.py` 的 `_add_table`）。

**8. 几个复杂度是经验值不是定理**

如希尔排序 `~O(n^1.3)`（依赖增量序列）、SPFA"平均 O(kE)"。写法沿用了教材惯例，
但严格说不精确。若你认为会误导学生，可以改写。

### 本轮修掉的自己的坑（说明我在哪些地方翻过车，可作审查线索）

1. 课件里**行内 `**加粗**` 标记没被解析**，原样显示成星号 —— 渲染后才发现。
2. 要点页文字**压到页脚**（字号自适应的估算偏乐观）。
3. 代码块**溢出灰底框**（改用绝对磅值行距，让高度可精确计算）。
4. 不换行文本框被渲染器**自动居中**，左边距忽宽忽窄（固定 `auto_size = NONE`）。
5. 表格说明**压住最后一行**（按实测行距校准）。
6. 代码块里的富文本解析会把 Python 的 `**` 幂运算符当成加粗标记 —— 已在
   `_add_runs` 里对 mono 内容直接跳过解析。
7. T6 样例输出写错（12 → 10）。
8. `deck.py` 结尾用了 python-pptx 私有 API `prs.slides.__iter__.__self__._sldIdLst`
   数页数 —— 本轮改成公共的 `len(prs.slides)`，并让 `build_all.py` 打印真实页数
   而不是 `len(SLIDES)+1`（两者恰好相等，但前者才是事实）。

**这 8 个坑里有 6 个是"渲染之后才发现"的**。所以闸门里保留了 `--render`，
并在 README 里写死了硬约束：改 `deck.py` 必须补跑一次 `--render`。
